# SmartDiag504 v0.4 Chatbot and VPS Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver one reproducible SmartDiag504 release archive with the public website, parts catalog, administrator image workflow, workshop operations, embedded chatbot, ERPNext/Beveren integration image, process-level redundancy, backup tooling, and documented two-VPS failover topology.

**Architecture:** Keep ERPNext/Frappe as the inventory and accounting source of truth. Run public web, operations web, platform API, AI gateway and workers as independently health-checked containers behind HAProxy and Caddy. Persist public catalog, reservations, work-order projection, heartbeats and chatbot audit in PostgreSQL; use the AI gateway as a guarded provider abstraction with deterministic fallback plus optional OpenAI-compatible or Ollama execution.

**Tech Stack:** Docker Compose v2, Caddy, HAProxy, React 19, TypeScript, Vite, FastAPI, SQLAlchemy, PostgreSQL 17, MariaDB 11.8, Valkey 8, ChromaDB, ERPNext/Frappe v16, Beveren FSM fork/patch, Python 3.12.

## Global Constraints

- ERPNext remains authoritative for item price, stock, invoice, payment, POS and accounting.
- Beveren `Service Order` remains the canonical OT; no second financial OT ledger is created.
- Canonical OT stages are exactly CREATED, QUOTED_BY_TECHNICIAN, PENDING_CUSTOMER_APPROVAL, PENDING_PARTS, READY_TO_INVOICE and INVOICED.
- Workshop bays are optional and disabled by default; Kanban is the default operational view.
- Product images can be uploaded by an administrator or imported from a rights-reviewed external result; Google Programmable Search is optional.
- The chatbot cannot invoice, collect payment, move stock, change prices, approve discounts or release vehicles.
- A single VPS deployment provides process/container failover only; host-level failover requires the included two-VPS plus witness topology.
- No live secret is committed; `.env` is generated on the VPS and excluded from release archives.
